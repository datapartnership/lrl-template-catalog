API reference

Once your access has been approved, this is the API you use to get the data.

Base URL: https://api.example.org

The API returns files and dataset metadata. Metadata comes back as Croissant 1.0 JSON-LD, which machine learning tools can read directly.

You need approved access first. See how to get access.

Authentication

Every request for data carries an access token, sent as a bearer token:

Authorization: Bearer <access token>

Each deployment uses exactly one way of signing in: built-in accounts (POST /api/auth/login returns a token), Microsoft Entra ID, or Keycloak. GET /api/auth/me returns the signed-in user.

A valid token is not enough on its own. The account must also be approved and active, so removing someone's access takes effect at once, even if their sign-in provider still issues tokens.

Never place a secret or token in a web page or a public repository.

Finding what to request

Browse the catalog on this site to choose a collection. Each collection page shows its ID and a few sample files. To list every file ID in a collection, call GET /api/catalog/collections/{id}/files, which needs no sign-in. File IDs also appear as @id in query results.

Endpoints

EndpointPurpose
GET /api/collections/queryA random sample of files, with their metadata, as Croissant JSON-LD
GET /api/files/{id}One file. Text arrives as shuffled paragraphs and audio as chunked, shuffled snippets.
GET /api/files/{id}/bundleZIP of a broadcast media file and its paired transcription. Needs the additional application step.
GET /api/collections/{id}/bundleZIP of a whole broadcast media collection with its paired transcriptions. Needs the additional application step.
POST /api/auth/loginSign in with a built-in account and receive a token (only where the deployment uses built-in accounts)
GET /api/auth/meCheck who the token belongs to

All of these need a token except POST /api/auth/login. The endpoints this website uses to browse the catalog are not covered here.

Querying a sample as Croissant

GET /api/collections/query returns a random sample of files, not a full listing, so it cannot be used to list everything.

  • Filters are optional and can be combined. They include media type, collection, provider, language, and keyword or theme.
  • limit sets how many files to return. The default is 30 and the maximum is 100.
  • With no filters, the API returns a random 80% of all files.
  • Each audio or video entry notes its paired transcription. The transcription itself needs the additional application step.

The response is a Croissant 1.0 JSON-LD document with one sc:Dataset entry per collection inside @graph. Each carries:

LevelWhat it carries
CollectionLicense (sc:license), creator and publisher, temporal coverage, language, screening flags (ddpv:piiScreening, ddpv:sensitiveContent), and data quality measurements (dqv:hasQualityMeasurement)
Text filesWord, character, token and page counts, a checksum (cr:sha256), and the keywords, themes and author added during tagging
Audio and video filesTechnical metadata such as duration, sample rate, channels and loudness (ebucore:*), a checksum (cr:sha256), the paired transcription, and keywords and themes

An outline of the shape, with most properties left out:

{
  "@context": [ "https://mlcommons.org/working-groups/data/croissant/", { "sc": "...", "cr": "...", "ddpv": "...", "dqv": "...", "ebucore": "..." } ],
  "@graph": [
    {
      "@type": "sc:Dataset",
      "sc:name": "Example collection",
      "sc:license": "...",
      "ddpv:piiScreening": true,
      "ddpv:sensitiveContent": false,
      "dqv:hasQualityMeasurement": [ ... ],
      "distribution": [
        {
          "@type": "cr:FileObject",
          "@id": "file-01",
          "sc:name": "bulletin-001.mp3",
          "sc:encodingFormat": "audio/mpeg",
          "cr:sha256": "...",
          "ebucore:duration": 576.6,
          "ebucore:sampleRate": 44100
        }
      ]
    }
  ]
}

This outline follows the example audio record on the Metadata page. The Metadata page links the full schemas, which list every property. Check a real response for the exact nesting of transcriptions and text files.

How files are delivered

KindWhat you get
TextPlain text made of the file's paragraphs in random order. Never the intact document. Text cannot be bundled into a ZIP.
AudioChunked, shuffled and delivered in snippets, in the same way as text.
Broadcast media with transcriptionsMedia files with paired non-verbatim transcriptions need an additional application step, to protect copyright. Once approved, they arrive as a ZIP with each media file and its transcription, a metadata.jsonld file, and a MISSING_FILES.txt note listing anything that could not be included.

Limits

  • Each user has a daily limit on text downloads, counted per UTC day. Failed requests do not use up the limit. Commercial subscribers have larger limits.
  • Queries return samples, as described above.
  • Downloads are logged for auditing.

Errors

StatusMeaning
400The request was not valid, for example asking for a ZIP of a text collection
401Not signed in, or the token has expired
403Signed in, but access has not been approved or the account is inactive
404Collection or file not found
422The file could not be read, for example an encrypted PDF
429Daily download limit reached. The response includes limit and used.

Examples

List the files in a collection, to find their IDs (no sign-in needed):

curl "https://api.example.org/api/catalog/collections/COLLECTION_ID/files"

Get a random sample of 10 files about health, as Croissant JSON-LD:

curl -H "Authorization: Bearer $TOKEN" \
  "https://api.example.org/api/collections/query?theme=Health&limit=10"

Download a text file as shuffled paragraphs:

curl -H "Authorization: Bearer $TOKEN" \
  "https://api.example.org/api/files/FILE_ID"

Download a broadcast media file with its paired transcription (needs the additional application step):

curl -H "Authorization: Bearer $TOKEN" -o file.zip \
  "https://api.example.org/api/files/FILE_ID/bundle"

Handle the daily limit from JavaScript:

const res = await fetch(`${API_BASE}/api/files/${id}`, {
  headers: { Authorization: `Bearer ${token}` }
});
if (res.status === 429) {
  const { limit, used } = await res.json();   // daily limit reached
}

If your API publishes a Swagger page, it is the authoritative list of parameters and response fields.
